# 设备写入所有权设计（单一写者不变量）

> 用户口述的核心约束：
> **「最终发送到设备上的动作要干净，不能是两种模式的动作同时发送给设备，会造成设备运动异常。」**
>
> 并且区分页面语义：**手机端视频页与预设页是两个页面**（进预设要关视频）；
> **电脑端是集成页面，进预设模式不应关闭视频**（可以边看视频边用预设），
> 所以要保的是「**清脚本**」而不是「关视频」。进预设模式 = **三件事**：清脚本 / 停快捷动作 / 开预设。

本文件把"谁能写设备"穷举成表，给出 **单一写者不变量（Single-Writer Invariant）**、
当前违反点、以及按该不变量推导出的修复方案。

---

## 1. 设备写入面穷举（`vendor/device/`）

BLE 上只有**一条写入流**（`channel._write`，`channel.py:222`），四类报文经它下发：

| 报文 | 生成点 | 性质 |
|---|---|---|
| `cmd_move` | `channel.move_to`（`:264`） | **运动帧**（连续流） |
| `cmd_limit` | `channel.apply_limits`（`:345`）、`set_limit`（`:281`） | 配置（限位/限速） |
| `cmd_mode` | `_handshake`（`:162`）、`connect`（`:310`）、`set_mode`（`:354`）、`set_profile` | 配置（A10 档案） |
| `cmd_oc_mode` | `_handshake`（`:164`）、`connect`（`:312`）、`set_oc_mode`（`:286`） | 配置（功率） |

### 1.1 运动帧的四个"所有者"（全部实际可达）

| 所有者 | 写点 | 是否查 `allow_move` | `force` | 节拍 |
|---|---|---|---|---|
| **script**（脚本同步） | `sync_engine.py:124` | ✅ `:93` | **True** | UI `timeupdate` 驱动，180ms 节流 |
| **preset**（预设播放） | `preset_player.py:168` | ❌ **不查** | **True** | `_play_one_loop` 段内等待 |
| **orgasm**（一键爆发） | `quick_moves.py:113` | ✅ `:108` | **True** | `span/speed` |
| **slow**（待机缓动） | `quick_moves.py:165` | ❌ **不查**（`:148` 只在 `_idle_watch` 里查） | **True** | 写死 `sleep(1.0)` |
| （手动） | `host_server.py:2505` → `channel.move_to` | ✅ 默认 | `force=True` | 单次 |

### 1.2 闸门结构性失效
`channel.py:252` 的闸门是 `if not self.state.allow_move and not force: return False`，
而**上表所有写点都传 `force=True`** ⇒ 闸门是**死代码**。
`force` 这个名字同时承担了三种含义（跳过行程重映射 / 跳过急停 / 强制写入），
这就是"急停挡不住缓动/预设"的根因——**不是忘了查，是闸门被参数名吃掉了**。

## 2. 不变量（Invariant）

> **I1（单一写者）**：任一时刻，至多一个"运动会话"处于 active；任何新运动会话的开始，
> 必须在**同一个请求内**依次把其它会话停掉，然后才开始写帧。
>
> **I2（新目标覆盖旧目标）**：落后/积压的运动帧必须被**丢弃**，只保留最后一次目标。
> 不允许把队列里的旧位置按序补发。
>
> **I3（配置写入不打断运动）**：`cmd_limit` / `cmd_mode` / `cmd_oc_mode` 不得与运动帧交错下发；
> 拖滑轨时不得每帧下发限位。
>
> **I4（急停是最高优先级的"零写者"）**：`allow_move=False` 时，**任何**运动会话都不写帧
> （不论 `force` 取值）。
>
> **I5（跳变后重新建立基准）**：seek / 加载新脚本 / 设备重连后，必须清空"上次位置"的抑制记忆，
> 否则第一帧被静默吞掉或按旧基准误判。
>
> **I6（急停停会话本身）**：急停除 `allow_move=False` 外，还必须把四个运动会话**全部停止**
> （用户裁定 2026-10-02「四个全受」）；解除急停**不自动恢复**任何会话，要动需用户重新启动。
> 与手机端（按拍拦帧、解除即续）的差异是**有意从严**：急停解除后动作自动恢复属于安全隐患。

### 会话转移矩阵（目标态）

| 新会话 ↓ \ 已有 → | script | preset | orgasm | slow |
|---|---|---|---|---|
| **script** | — | **停 preset** | 停 orgasm | 停 slow |
| **preset** | **清 script**（不停视频） | — | 停 orgasm | 停 slow |
| **orgasm** | 停 script | 停 preset | — | 停 slow（已有 `:88`） |
| **slow** | 停 script | 停 preset | 停 orgasm（已有 `:126`） | — |
| **急停 off→on** | **全部停止 + 静默（I4+I6，用户裁定）** | | | |

现状：只有 `orgasm→preset`（`host:2556`）与 `orgasm↔slow`（`quick_moves.py:88,126`）两格是通的，
其余全部缺失 ⇒ 矩阵**严重不对称**。

## 3. 当前违反点（按不变量归类）

| 违反 | 位置 | 后果 |
|---|---|---|
| **I1** script 开始时不停 preset | `host:2455-2464`、`ui/app.js:1584` | 预设段帧与脚本帧交错 → 设备来回抖 |
| **I1** preset 开始时不停 orgasm/slow | `host:2576-2577` | 预设与爆发/缓动同时写 |
| **I1** orgasm/slow 开始时不停 script | `host:2555-2557` | 脚本帧仍在推进目标 |
| **I4** preset / slow 不查 `allow_move`、全部 `force=True` | `preset_player.py:168`、`quick_moves.py:165`、`channel.py:252` | **急停无效** |
| **I2** tick 无时间戳/无背压 | `sync_engine.py:84-88` + `host:2465-2468` | BLE 卡顿后按序补发旧位置（"追帧"抖动） |
| **I2** 在途协程不被取消 | `channel.submit`（`:56-58`）超时不 `cancel` | 断开/急停后仍落帧 |
| **I3** 每次 `/api/settings` 保存都 `apply_limits()` | `host:2422` → `:3841` | 拖滑轨时与运动帧交错；`submit(timeout=10)` 阻塞 |
| **I5** 断连不清 `_last_pos` / `_ready` / 限位 | `channel._cleanup`（`:196-209`）、`sync_engine.py:27` | 重连后首帧被抑制、急停态残留 |
| （帧内容）区间外发满速帧 | `sync_engine.py:97-100` + `124`（`int(0) or None` → `max_speed`） | 播放头在动作点范围外时一次满速移动 |

## 4. 修复方案

### 4.1 引入显式仲裁：`DeviceArbiter`（推荐，一次性解决 I1）

在设备层加一个只做仲裁的小对象（不碰 BLE），所有会话启停都走它：

```python
# vendor/device/arbiter.py（新文件）
class MotionOwner:            # 用 str 常量即可："script" | "preset" | "orgasm" | "slow"
    ...

class DeviceArbiter:
    """保证 I1：任一时刻至多一个运动会话 active。所有 start/stop 都从这里过。"""
    def __init__(self, channel, quick, preset, sync, on_change=None):
        self.ch, self.quick, self.preset, self.sync = channel, quick, preset, sync

    def _stop_all_except(self, keep: str) -> None:
        if keep != "sync":
            self.sync.stop()
        if keep != "preset":
            self.preset.stop()
        if keep != "orgasm":
            self.quick.stop_orgasm()
        if keep != "slow":
            self.quick.stop_slow()

    def start_script(self, path: str) -> dict:
        res = self.sync.start(path)                 # 先校验脚本存在
        if res.get("ok"):
            self._stop_all_except("sync")           # 成功才停别人（避免"停了一片却没跑起来"）
        return res

    def start_preset(self, action: str) -> dict:
        self._stop_all_except("preset")             # = 用户要的三件事之一：清脚本 + 停快捷动作
        return self.preset.start()

    def start_orgasm(self) -> dict:
        self._stop_all_except("orgasm")
        return self.quick.start_orgasm()

    def start_slow(self) -> dict:
        self._stop_all_except("slow")
        return self.quick.start_slow()

    def stop_all(self) -> None:                     # 急停/断开/退出共用
        self._stop_all_except("")
```

宿主四个路由改成只调 arbiter（`/api/sync/start`、`/api/preset`、`/api/quick` 的爆发/缓动分支），
前端**不再自己做仲裁**（`ui/app.js:2058` 的 `syncStop()` 可保留为 UI 提示，但真相在宿主）。

### 4.2 修 `force` 的三义性（解决 I4）

```python
# channel.py:248-253
async def move_to(self, percent, speed=None, force=False, raw=False,
                  *, bypass_estop: bool = False):     # 只有急停复位路径能传 True
    if not self.state.allow_move and not bypass_estop:
        return False
```
- `raw=True` 保留原义（跳过行程重映射，只做反转）
- 四个运动写点**一律不传** `bypass_estop` ⇒ 急停对四方全部生效
- `preset_player.py:168`、`quick_moves.py:113/165` 的 `force=True` 改为 `raw=False`（或按各自语义取值）
- `_slow_loop` 补 `if not allow_move: await asyncio.sleep(0.25); continue`（对齐 `:148`）
- **急停路由本身**（`/api/quick {kind:"stop",on:true}`）调 `arbiter.stop_all()` + `allow_move=False`（I6）；
  解除分支（`on:false`）只复位 `allow_move`，**不重启任何会话**

### 4.3 让"快照"取代"队列"（解决 I2）

```python
# sync_engine.py：改为只保留最新目标 + 单调时间戳
def tick(self, t_sec: float) -> None:
    if not self.active:
        return
    self._pending = float(t_sec)                    # 覆盖，不排队
    if self._inflight:
        return                                      # 上一帧还没写完就丢弃本次
    asyncio.run_coroutine_threadsafe(self._drain(), self.loop)
```
并在 `channel.submit` 超时后 `fut.cancel()`；`stop()` 时把 `_pending=None`、`_inflight=False`。

### 4.4 配置写入与运动解耦（解决 I3）

- 拖拽期间**不**下发 `apply_limits()`：`saveVl` 改为 `pointerup` 后落盘，或宿主对 `video_link` 变更做 300ms 合并、只在值真的变化时下发。
- `apply_limits()` 从 `/api/settings` 的**同步路径**移出，改由 BLE 循环内的低优先级任务执行，避免 HTTP 线程 `submit(timeout=10)` 阻塞。

### 4.5 会话边界清理（解决 I5）

- `_cleanup()` 复位：`allow_move=True`、`_ready=False`、`limit_min/limit_speed`、`state.recent=[]`；
- `sync.stop()` / `load()` 复位 `_last_pos=None`（已有 `:61`，补 `stop()` 路径）；
- 设备重连成功后 `note_external()` 让缓动重新计时。

## 5. 进预设模式 = 三件事（按用户口径落地）

```
用户点「播放预设」（两段式确认第二击）
        │
        ├─ ① 清脚本：POST /api/sync/stop  →  SYNC.on=false，停止 tick
        │            （保留 vlMed.path 与 <video> 播放状态——电脑端集成页不清视频）
        ├─ ② 停快捷动作：POST /api/quick {kind:"orgasm",on:false}
        │                POST /api/quick {kind:"slow",on:false}
        └─ ③ 开预设：POST /api/preset {action:"play"}
```
**原子性要求**：这三步必须在**同一个宿主请求**里完成，否则中间窗口仍有两个写者。
实现方式：宿主 `/api/preset` 的 `play/start` 分支先调 `arbiter.start_preset()`（内部即 `_stop_all_except("preset")`）。

> 手机端对照：`AppViewModel.kt:3530-3539` 的 `startPresetPlayback()` 是四件事
> （清脚本 / **关视频** / 停快捷动作 / 开预设）。第 ② 件"关视频"是**手机端页面结构的产物**
> （视频页与预设页分离），**PC 端集成页不采纳**——这是**有意分叉**，应写进注释，
> 避免下一个人"对齐手机端"把视频关掉。

反向（脚本 → 预设的反面）：**预设播放中加载脚本 / 开播视频**时，同样走 `arbiter.start_script()`：
停 preset + 停 orgasm/slow（保留视频播放），即用户本次提出的规则 P-2。
