## 2. 手机端的"联动二次确认"语义（两个方向；本仓库已做了一半）

> ⚠️ **更正**：本文件第一版与 `REVIEW-视频联动.md` 里我写的"本仓库完全没有对称确认"是**错的** ——
> 我漏看了已实现的那一半。本仓库 `#vlPresetToggle` 的两段式确认（`ui/app.js:2030-2076`）确实覆盖了手机端
> 「脚本模式 → 预设模式」这个方向。下面按**两个方向**分别对照。

### 方向 A：脚本模式 → 进入预设模式

| | 手机端 | 本仓库 |
|---|---|---|
| 入口 | `requestPresetPlay()`（`AppViewModel.kt:3507-3519`） | `#vlPresetToggle` → `vlPresetButton()`（`ui/app.js:2055-2076`） |
| 触发判据 | **脚本已加载 `_script != null` OR 视频在播 `_videoActive`**（`AppViewModel.kt:3514`） | `SYNC.on`（= 设备已连 **且** 脚本加载成功，`ui/app.js:2033-2036`） |
| 交互 | 弹 `AlertDialog`：标题「切换到预设模式？」、正文「确认将退出脚本模式（清空已加载脚本）。停止预设后脚本同步不会自动恢复。」（`Screens.kt:3717-3730`） | 按钮变红 + 文案「将退出联动，确定请再点击」，5 秒后自动撤销（`ui/app.js:2030,2047-2052`） |
| 确认后动作 | **四件事**：① 清空脚本 ② 关内置视频 ③ 停快捷动作（orgasm+slow）④ 开预设（`AppViewModel.kt:3530-3539`） | **一件**：`syncStop()` ④ 开预设（`ui/app.js:2056-2060`） |

**结论：方向 A 本仓库"有确认，但判据更窄、动作更少"** ——
- 判据窄：视频在播但没脚本/没连设备时，手机端会拦、本仓库不拦；
- 动作少：漏了**停快捷动作**（`POST /api/quick{orgasm:false}` / `{slow:false}`）。这是真实遗漏。

### 方向 B：预设模式 → 加载脚本/开播视频（手机端的 `scriptLoadConfirm`）

| | 手机端 | 本仓库 |
|---|---|---|
| 入口 | 手动加载脚本 `pendingManualScript`（`AppViewModel.kt:3541-3549`） | 点视频卡片 → `openVideo()` → `<video> play` 事件 → `syncStart(vlMed.path)`（`ui/app.js:1446-1456,1584`） |
| 确认 | 弹「加载脚本？——当前处于预设模式，加载脚本将停止预设播放并退出预设模式。」（`Screens.kt:3732-3743`） | **没有** |
| 确认后动作 | `_presetPlayer.value?.stop()` 再加载脚本（`AppViewModel.kt:3546`） | 无仲裁；`SYNC.on` 变 true 后预设循环**继续跑**，两个 `force=True` 写者抢同一 BLE 通道 |

**这一半确实完全没有**。证据：全仓 `DEV.preset.playing` 只被**赋值**（`ui/app.js:2272`），**从未被读取**；
`syncStart()`（`ui/app.js:2394-2400`）不检查预设状态；宿主 `/api/sync/start`（`host_server.py:2455-2464`）也不 `preset.stop()`。

**所以准确的说法是**：方向 A 你做了（值得保留），方向 B 缺失 —— 也就是手机端那对"对称确认"在本仓库是**单向的**。

对照本仓库：`vlInScriptLink()`（`ui/app.js:2033-2036`）判据是 `SYNC.on`（= 设备已连 + 脚本加载成功），**比手机端窄**；
`vlPresetButton` 第二击只做 `syncStop()`（`ui/app.js:2058`）+ `run()`，**没有③停快捷动作**。

对照本仓库：
- `vlInScriptLink()`（`ui/app.js:2033-2036`）判据是 `SYNC.on`（= 设备已连 + 脚本加载成功），**比手机端窄**：视频在播但没脚本/没设备时手机端也会弹确认，本仓库不会。
- `vlPresetButton` 第二击只做 `syncStop()`（`ui/app.js:2058`）+ `run()`，**没有③停快捷动作**。
- BOOST / RANDOM 被从 `vlPresetButton` 里摘出来了（`ui/app.js:2073-2074`）。

**修正后的判定**：
- 摘掉 BOOST/RANDOM 的确认 **可以接受**（手机端 `toggleBoost` 只翻标志不启动循环，R02-Q3 的判据成立），
  **但前提是补上手机端真正更重要的两件事**：① `startPresetPlayback` 语义里"停快捷动作"；② 反向确认（预设→加载脚本）。
- 真正的回退是 **`vlPresetButton` 第二击漏停快捷动作**，以及**判据比手机端窄**。

## 3. 修复建议（按手机端规范排序，逐条给最小改动）

### 3.1【已撤回】`反转方向` 不需要修（第 2 轮更正）

> **⛔ 本条建议作废。** 第 1 轮的"取值改回 `device.reversed`"是**误判**：
> `host_server.py:3858` 紧接着就用 `dev["reversed"]` 赋了正确值，用户开关**本来就是有效的**。
> 探针 `review/probes/probe_reversed_final.py` 5 个用例全部与 `device.reversed` 一致。
> `:3840` 的 `reversed_` 只是**死参数**（值立刻被覆盖）——可选清理项，非缺陷。
> 详细更正见 `REVIEW-视频联动.md` §4.1。

### 3.2【必改】`伪装设备（VorzePiston 模式）` 映射写反
手机端真值：`setSpoofEnabled(true)` → `setA10Mode(1)`（`AppViewModel.kt:807-810`），
而 `DeviceProtocols.kt` / `protocols.py:38,41-42` 的权威表是 `ServeU=0`、`VorzePiston=1`。
- 本仓库：`host_server.py:3860` 写成 `("vorze", "serveu")[a10]` ⇒ `1→serveu`，**反了**。
- **改法**：`_tp = ("serveu", "vorze")[int(dev["a10_mode"])]`。

### 3.3【必改】删掉设置页里 AI 自造的两项
| 项 | 位置 | 手机端对照 | 处置 |
|---|---|---|---|
| 「播放视频时同步驱动设备」开关 | `ui/index.html:833-836` + `ui/app.js:2372` | **不存在**（手机端视频在播就同步，无开关） | **删**（顺带消灭 R01-A8「关掉不生效」） |
| 「同步延迟补偿（ms）」数字输入框 | `ui/index.html:837-838` + `ui/app.js:2373-2375` | 只有 4 个 ±按钮（`Screens.kt:1842-1857`） | **删输入框**，保留 `[data-delay]` 4 个按钮 |

### 3.4【必改】删掉"僵尸键 + 残骸"，恢复单一真相
把 `device.{orgasm,slow}` 收敛成手机端真正会读的那些，其余删掉：
```python
# host_server.py:3844-3852 改为只保留手机端确实从 device 段读的东西
vl_cards = {...}                                    # ← 整段删除
d["quick"].apply(                                   # ← 整段删除
# 保留：
if dev.get("slow", {}).get("idle_detect_seconds") is not None:
    d["quick"].slow.idle_detect_seconds = int(dev["slow"]["idle_detect_seconds"])
```
同时删掉 `ui/app.js:2326-2327`（读不存在的 `#setSlowSpeed`/`#setOrgasmSpeed`）与 `2320-2321` 里对应的 `Object.assign` 分支。
**理由**：手机端 `QuickMoves.loadSlow()/loadOrgasm()`（`QuickMoves.kt:346-372`）读的是 `prefs["slow_move"/"orgasm_move"]` 这一份**权威存档**，UI 写的就是它；不存在"第二份只写不读的键"。

### 3.5【应对齐】`待机缓动·空闲判定秒数` 的合法范围
| | 范围 |
|---|---|
| 手机端 UI 步进器 | 1–600（`Screens.kt:1775-1776`） |
| 手机端**内存/读档** | 1–60（`QuickMoves.kt:368` `coerceIn(1, 60)`） |
| 本仓库设置页输入框 | `min=1 max=600`（`ui/index.html:773-774`） |
| 本仓库设备层 | 无上限校验，`int(...)` 直收（`host_server.py:3854-3855`） |

⇒ 手机端**实际生效上限是 60**，本仓库能存 600 且不夹紧。**建议按手机端内存口径 `coerceIn(1,60)`**，或至少与手机端上限 600 保持一致并给 `quick_moves` 加夹紧。

另：`跳过无动作部分` 的**默认值两端不一致** —— 手机端 `skipIdleEnabled` 默认 `false`（`AppViewModel.kt:896`）、阈值默认 **60 秒**（`AppViewModel.kt:899`，UI 步进 5–3600）；本仓库默认 `True` + **3 秒**（`ui/app.js:2323-2324` 用 `d.skip_idle !== false`、`d.idle_threshold || 3`）。建议对齐成手机端的 `false / 60`，或至少不要用 `!== false` 这种"缺键即视为开"的默认。

### 3.6【应对齐】预设速度滑轨：补持久化（而不是删键）
我上一版建议"要么落盘、要么删键"。按手机端实际做法，**应当落盘**：
手机上 `prefs["presetSpeed"]` 防抖持久化（`AppViewModel.kt:206-217`），而本仓库 `device.preset_speed` 这个键**存在但前端从不写**，
`_apply_device_settings`（`host_server.py:3869-3870`）反而用磁盘旧值去覆盖运行中的滑轨值 ⇒ "拖了滑轨，下次保存设置又被拨回去"。
- **改法**：`#vlPresetSpeed` 的 `onChange` 加 300ms 防抖，同时发
  `POST /api/preset {action:"speed",speed:v}` **和** `POST /api/device/settings {preset_speed:v}`；
  启动时用 GET `/api/settings` 的 `device.preset_speed` 预置滑轨（现在是从 `DEV.preset.speed` 取，见 `ui/app.js:2276-2279`）。
- 顺带：手机端在 100 时显示「（原始）」并给「恢复默认」按钮，可一并复刻（`Screens.kt:3856,3865-3867`）。

### 3.7【方向 A：脚本→预设】把两段式确认补全（你已做的部分保留）
手机端 `startPresetPlayback()` 四件事（`AppViewModel.kt:3530-3539`），本仓库应为**三件事**：
- ① 清脚本（停同步）→ **已有**（`syncStop()`，`ui/app.js:2058`）✅
- ② 关内置视频 → **PC 端刻意不做**：手机端视频页与预设页是两个独立页面，所以进预设要关视频；
  电脑端是集成页面，允许**边看视频边用预设模式**，必须保留 `<video>` 播放（只清脚本）
- ③ **停快捷动作 → 缺**（`stop_orgasm` + `stop_slow`）
- ④ 开预设 → **已有** ✅
- **改法（最小）**：`vlPresetButton` 第二击里，`syncStop()` 旁边补两个请求：
  `POST /api/quick {kind:"orgasm",on:false}` 与 `{kind:"slow",on:false}`；或更稳地移到宿主 `/api/preset {action:"play"}` 分支里统一仲裁。
- **改法（判据）**：`vlInScriptLink()`（`ui/app.js:2033-2036`）把"视频在播"也算进去，对齐手机端
  `_script != null || _videoActive`（`AppViewModel.kt:3514`）—— 现在只看 `SYNC.on`，视频在播但没脚本时不会拦。

> 完整设计见 [设备写入所有权设计](设备写入所有权设计.md)：核心是**单一写者不变量**——
> 最终发给设备的动作必须只有一个来源，不能两种模式的动作同时下发。

### 3.8【方向 B：预设→脚本】补上缺失的另一半仲裁（手机端 `scriptLoadConfirm`）
手机端在预设模式中手动加载脚本会弹确认「加载脚本？——当前处于预设模式，加载脚本将停止预设播放并退出预设模式。」
（`Screens.kt:3732-3743`），确认后先 `_presetPlayer.value?.stop()` 再加载（`AppViewModel.kt:3546`）。

本仓库对应入口是**点视频卡片开播**（`openVideo()` → `<video> play` → `syncStart()`，`ui/app.js:1446-1456,1584`），
目前**无任何仲裁**：`DEV.preset.playing` 只被赋值、从未被读取（`ui/app.js:2272`），
`syncStart()`（`2394-2400`）不查预设，宿主 `/api/sync/start`（`host_server.py:2455-2464`）也不 `preset.stop()`。

- **改法（最小，前端）**：`syncStart()` 开头判 `DEV.preset.playing`，是则先
  `POST /api/preset {action:"stop"}`（并按 §3.7 停快捷动作）再发 `/api/sync/start`。
- **改法（更稳，宿主）**：在 `/api/sync/start` 里统一仲裁（`preset.stop()` + `stop_orgasm()` + `stop_slow()`），
  前端只做展示 —— 这样头显/脚本调用方也一并受保护。
- **可选（照抄手机端体验）**：像"将退出联动"那样给一个可见确认；但本仓库视频页与预设同屏，
  直接停预设 + 停快捷动作通常比弹窗更顺手，**建议只在宿主侧仲裁，不弹窗**。

---

## 4. 一句话总结

**设置页只需保留手机端 `设备与同步` 的那 6 张卡对应的东西**（空闲判定秒数 / 跳过无动作 / 手动位置 / 延迟±按钮 / 设备信息 / 伪装·反转·狂暴），
**删掉 AI 自造的两项**（"播放视频时同步驱动设备"开关、"同步延迟补偿"输入框）与两个残骸（`#setSlowSpeed`/`#setOrgasmSpeed`）；
**联动页持有手机端控制页 4 张卡 + 预设页的速度滑轨**，并补上"预设↔同步"的双向互斥（含停快捷动作）。
