## 板块一：视频联动与媒体库

### 现状
- **Nexus 无播放器、无媒体库**：ui/index.html 无 `<video>` 元素（本次 grep 零命中）；现有 UI 是 5 页管理控制台（仪表盘/DLNA 服务器/AI 字幕/设备同步/设置，ui/index.html:161-197），前端与 API 同端口 8790 环回（host_server.py:105），fetch 轮询 `/api/state`（host_server.py:5-12 docstring 自述）。
- **可复用底座已在**：DLNA 服务的 HTTP Range 解析与流播（vr_dlna.py:343-346, 1139-1177）、funscript 枚举 `/scripts?base=`（vr_dlna.py:622-680, 1208）、`.strm` 代理（:1230）、DLNA 启停与 roots API（host_server.py:2216-2220）、adb 脚本/视频分发（funscript_sync.py:11-17）、`data/vr_dlna_funscript_config.json`（本次 ls data/ 确认存在）。
- **pywebview 现实**：WebView2（Chromium 内核）frameless 窗口 + js_api 桥（host_server.py:3493-3506；桥方法 win_minimize/pick_folder/pick_file，:3255/:3286/:3306；前端调用 ui/app.js:849, 1056）。HTML5 能力 = Chromium 能力。
- **手机端参照（考古）**：PlayerLink 统一抽象下双链路互斥（AppViewModel.kt:124-141）、20ms tick 状态映射（VideoPlayerController.kt:191-212）、媒体库零海报零聚合（grep thumbnail/poster 全工程零命中）、续播 LRU 200（AppViewModel.kt:1976-2024）、脚本三级查找（AppViewModel.kt:2303-2379/1031-1096/3716-4134）。

### 推荐方案
**A. 播放内核 = HTML5 `<video>` + host 本地 HTTP Range 流**（三选一对比后选此）
- 流服务：把 vr_dlna.py 已验证的 Range 流播逻辑（:343-346 解析 / :1139-1177 回包）抽公共函数挂到 8790 的 `/media/stream?path=…`（严格环回 + 路径必须落在已配置媒体根内）；或直接引用 8899 DLNA URL（免重复实现，但绑死 DLNA 开关状态，建议前者）。
- 状态桥：JS 以 20ms 节流（或 requestVideoFrameCallback）读 `currentTime/paused/playbackRate` → pywebview api 上报，等价替代手机 VideoPlayerController 的 tick 循环（VideoPlayerController.kt:191-212，考古）；控制下行用 host `evaluate_js` 操作 `<video>`。这一层同时产出「播放器状态对象」，是板块二/三/四共用的消费源。
- 编解码兜底：`<video>` 起播失败（error/canplay 超时）→ host 用 **PyAV remux 成 fMP4** 再流（PyAV 17.1.0 实测在 venv 且自带 FFmpeg DLL；全仓无 ffmpeg CLI，走库内而非子进程）。remux 解决容器问题（mkv 等）；HEVC 等编码依赖 Windows HEVC 扩展，**一期明确不承诺**。
- 新增侧边导航「播放 / 媒体库」页，全部沿用现有深色 tokens（ui/styles.css:16-66）。

**B. 媒体库 = host 端多文件夹扫描 + 索引 + PyAV 缩略图**
- 配置 N 个本地媒体文件夹（`pick_folder` 桥现成，host_server.py:3286）；扫描记录 path/mtime/size 落 `data/library.json`（或 SQLite），按 mtime 增量。
- 缩略图：PyAV 在 ~10% 进度处抽 1 帧 → JPEG → `data/thumbs/`（key=path+mtime），后台低优先级批量生成。**DLNA 浏览路径保持零探测不动**（vr_dlna.py:9-11 的网盘秒开设计），缩略图只服务库页。
- 布局：**海报墙（默认）+ 文件夹视图（切换）双模式**；多文件文件夹的封面 = 最近播放项缩略图 + 进度角标（呼应考古里用户对手机端「无聚合、浏览即文件名列表」的观察）；单文件文件夹直接显示文件卡。筛选：有无 funscript 徽标（复用 vr_dlna.py:622-680 枚举逻辑）、最近播放、未看完。
- 续播：桌面直接用 SQLite/JSON 表存 path→position，**不必复刻手机 SHA-256 截 128 位的压缩技巧**（那是 AppViewModel.kt:1976-2024 为手机存储设计的），但保留「结尾 1s 内视为看完即清除」语义（考古同段）。

**C. funscript 联动复用（两条链都不新建协议）**
- 内置播放：库项 → 三级脚本查找直译（同目录同名 → 脚本文件夹索引 → DLNA `/scripts` 远程索引）→ host 内 SyncEngine-Python（20ms 时钟 + 二分查段 + computeMove 三十行直译，Funscript.kt:42-54 + SyncEngine.kt:220-243，考古）→ 设备通道 **bleak（新增）或 adb 离线推送（funscript_sync.py 现成）**。
- 投头显联动：库项一键「DLNA + 联动」——视频目录不在 DLNA roots 则经 `/api/dlna/roots`（host_server.py:2220）临时挂入 → 桌面作为 **TCP 客户端 connect 头显:23554**（4 字节小端长度前缀 + JSON 帧，PlayerProtocol.kt:84-99 协议规约照考古复刻，下行必须字符串值 JSON :214-229）→ 同一 SyncEngine-Python 驱动玩具。手机在此场景的角色由桌面接管，协议与角色拓扑（README 第二节 DeoVR 组合，考古）完全一致。

### 备选
- **libmpv 嵌入**：codec 全能 + ASS 原生渲染，但 pywebview 无原生渲染面嵌入点，只能「独立 mpv 窗口叠放 + IPC」或弃 webview 换纯原生窗——与「UI 走现有 web 深色风格」直接冲突，打包体积与窗口管理成本高。**仅当 HEVC/老编码覆盖成为硬需求时再立项**。
- **系统默认播放器外部调起**（os.startfile）：零播放器工作量但完全失控（无进度无联动）；仅 mpv.exe 可用 `--input-ipc-server` 命名管道拿全控，可作为「外部播放器联动」的兜底形态，与 DeoVR TCP 链并列。
- **媒体库分期降级**：一期只做文件夹视图 + 续播 + 脚本徽标（无缩略图管线），卡片用首字符占位（深色风格下成立），缩略图管线二期补——扫描/索引先行不阻塞。

### 工作量档位：**M**（拆解：流服务 + JS 桥 + 播放页 UI = S–M；媒体库扫描/索引/筛选/续播 = S–M；PyAV 缩略图管线 = M；SyncEngine-Python 数学直译 = S；**设备实时通道 bleak = M，且是全新增量**——本次 grep bleak/bluetooth 全仓零命中；TCP 客户端联动 = S）

## 板块二：预设集成

### 现状（考古）
- 手机端预设 = 底栏独立 Tab（Screens.kt:3680-3745），三卡片（行程滑条 / 24 卡网格带 Canvas 波形缩略图 / 速度 + BOOST·播放·RANDOM）；数据全部硬编码于 PresetDefs.kt:87-462（2 段式 + 22 波形，纯字面量）；PresetPlayer 独立协程逐段 moveTo + 单调时钟等待（PresetPlayer.kt:126-147），**完全不碰媒体时钟**（:26-53）。
- 与脚本同步是互斥两套驱动：进预设清空脚本且停止后不自动恢复（AppViewModel.kt:3507-3554；PresetPlayer.kt:18-19）；QuickMoves（急停/爆发/缓动）是并列模块，但 UI 挂在控制页与视频页**共用**（Screens.kt:1231-1362）——手机自己已经用「预设独立页 + QuickMoves 常驻播放页」回答过一次布局问题。
- 桌面现状：Nexus 无预设、无 BLE 通道（本次 grep 零命中）；设备下发现状只有 adb 推送（tools/adb）。

### 推荐方案：**独立页为主 + 播放页常驻 QuickMoves 条（混合案）**
1. **独立「预设」导航页**，完整平移三卡片：行程滑条（共用设备参数面）→ 24 卡网格（波形缩略图：考古已文档化的 buildPresetPoints 四象限 + felt-window 裁剪算法，Screens.kt:4068-4097，Canvas→`<canvas>`/SVG 直译，顶点序列缓存防重算的教训照搬）→ 速度滑条 1..500 + BOOST/播放/RANDOM 圆钮。
2. **播放页顶/底栏常驻三圆钮：急停/爆发/缓动**——不把 24 卡塞进播放页。判据来自数据结构本身：预设与媒体时钟零耦合（PresetPlayer.kt:26-53），放播放页没有「同步增强」的信息价值，反而带入互斥确认弹窗（播放前若脚本已加载弹确认，AppViewModel.kt:3507-3519）；而 QuickMoves 天生为「与播放共存」设计（pauseForPlayer/resumeForPlayer，QuickMoves.kt:141-184 考古）。
3. **数据与引擎归 host**：24 预设机械转成 JSON 常量（考古 portNotes：纯字面量零逻辑）+ toSegments/loopTravel/loopDurationMs 十几行纯函数用 Python 实现；PresetPlayer-Python 与 SyncEngine-Python 共享同一条 moveTo 加工链（allowMove 急停检查 → 行程重映射 → 速度×span/100 → 钳上限 → 反转，BleDeviceService.kt:711-725，考古标注「必须复刻一次、两引擎共用」）与 [0x01,percent,speed] 线帧（DeviceProtocols.kt:92-115）。
4. **互斥编排升级为 host 端模式管理器**：`{script_sync | preset | quickmoves}` 状态机；进预设 = **挂起**脚本同步（保留已加载脚本），退预设 = 自动恢复——直接修复考古记录的「清空脚本且不自动恢复」痛点（PresetPlayer.kt:18-19），这是对手机行为的有意改进而非照搬。
5. **保留的护栏（考古明确警告的语义陷阱）**：waitMs = naturalMs×段速÷实际速度的绝对速度语义（PresetPlayer.kt:126-147）；durationMs≤0 时 speed 兜底 1 防 Infinity（PresetDefs.kt:33-36）；BOOST=500 激活记忆原速、取消恢复、**不持久化**（AppViewModel.kt:3489-3505）。

### 备选
- **完全独立页（手机平价）**：改动最小、零集成风险，但播放中想急停要切页——连手机都把 QuickMoves 放到了播放页，桌面照抄会倒退。
- **播放页侧栏全量预设面板**：入口最浅，但行程+24 卡+速度塞侧栏过密；互斥确认弹窗出现在沉浸播放场景里更打断；不推荐为主案。若坚持单页，可退化为「侧栏只放 RANDOM+速度+当前预设」的轻面板。

### 工作量档位：**S–M**（数据 JSON 化 + host 引擎（toSegments/循环/RANDOM/BOOST）= S；完整三卡片 UI 含波形缩略图 = M；模式管理器 = S。若 bleak 未落地则整体 +M）

## 板块三：实时动作识别预留

### 现状
- **两仓零生成能力**（考古 grep yolo/光流/动作识别/funscript 生成 全部零命中；`AI Funscript` 目录为空占位）；业界成熟路线全是离线生成（FunGen/Funscript-Flow 等，考古 WebSearch 结论），实时属探索。
- **但模板与栈齐全（本次实测）**：AI 字幕管线是同构模板（抽流→分块→GPU→SSE→recommended_chunk_sec，考古）；SSE 流式桥现成（stream_bridge.py:8-25）；字幕服务「独立子进程 + stop/reclaim 释放显存」现成（host_server.py:5-12 docstring、/api/subtitle/reclaim :2256）；torch 2.11.0+cu128 CUDA 可用、PyAV 17.1.0 可抽帧（本次实测）；onnxruntime 无 GPU provider（本次实测）→ **视觉模型必须走 torch**；无 ffmpeg CLI → 抽帧必须走 PyAV。

### 推荐方案：**契约先行 + 离线先行**
1. **控制面**（对齐字幕四件套，host_server.py:2249-2258 同构）：`/api/actions/{config,start,stop,status,reclaim}`；引擎挂 `vendor/actions` 独立子进程，显存治理复用 R56/R57 空闲回收模式（考古）；`actions.enabled` 默认关，随 settings + /api/state 暴露（配置开关）。
2. **输入抽象 `FrameSource`**：
   - `LocalFileFrameSource`（一期）：PyAV 定频/定点抽帧（如 1fps 或 10% 处密集采样）→ tensor；直接吃媒体库 path 与 DLNA 根目录文件，与 vr_dlna.py:9-11 的「浏览零探测」不冲突（识别服务独立探测，不碰浏览路径）。
   - `ChunkFrameSource`（二期预留，实时）：HTTP POST 帧块（JPEG + video_start_ms + 服务端下发 recommended_chunk_sec），协议与 `/transcribe` 同构（stream_bridge.py:8-25）；桌面 webview 侧用 `<video>`→canvas.drawImage→toBlob 低帧率抽帧（1–5fps，够节奏检测、不够精细追踪——如实标注能力边界）。外部头显无帧通路（考古局限），明确不支持。
3. **输出抽象**：标准 funscript 事件流——SSE 增量 `data:{"type":"delta","actions":[{"at":ms,"pos":0-100}…]}` + 最终落盘 .funscript 到视频同目录/库。消费端三路现成：内置播放器进程内注入（免 HTTP 一跳，省掉手机侧 4~9s 滞后的一部分，考古 portNotes）、funscript_sync.py adb push、手机远程脚本源索引。
4. **mock 引擎先行**：恒定正弦脚本引擎先用 S 档成本把「控制面→SSE→播放器注入→热力图显示」整条链验证通——这就是「预留」的可交付形态；真引擎（PyAV 抽帧 + torch 检测/光流）单独立项。音频能量启发式仅作未验证兜底候选（考古 notes：搜索未命中 funscript 场景直接方案）。
5. **形态纪律**：识别引擎属 vendor 改动，沿用 dist-app 同步纪律（考古 docs/AI-SUBTITLE-STATUS.md 运行形态节）。

### 备选
- **独立 CLI 形态**（tools/actions_gen.py 离线跑）：更省事，但失去「库内一键生成」入口与统一显存治理；可作为一期降级形态，接口契约不变。
- **实时优先**：风险集中在 webview 帧捕获 fps/延迟与 GPU 预算，不建议一期。

### 工作量档位：控制面 + 输入输出抽象 + mock 引擎 = **S**；离线引擎本体（模型选型/调参）= **L**；实时帧流通道 = **M–L**。建议一期只做 S 档预留，L 档单独立项。

## 板块四：遥控深度联动

### 现状（考古汇总）
手机遥控唯一链路 = BLE HID 虚拟键盘发 F13–F19（HidRemoteController.kt:52-60）；**只发不收**（激活态纯视觉、与 PC 真实态漂移，RemoteScreen.kt:239-244）；动作集硬编码 7 个、幅度由 PC 端「调整幅度」决定（README.md:181）；Android 9+ 门槛 + 4 步人工配对 + Windows 不回连需 10×1s 重试（RemoteScreen.kt:192-214；HidRemoteController.kt:293-317）；不能控播放器（键盘页无 consumer usage，:390-414）；PC 端只有 ServeUCentral 全局键盘钩子、无 API（:31-47 注释）；F20–F24 空闲。Nexus 侧：8791 LAN HTTP 面板 + Origin 栅栏（host_server.py:2183-2186）与 `/api/headset/status`（:2657）已验证手机↔Nexus LAN 通道可用；前端无 WS（本次 grep 零命中）。

### 推荐方向
把「遥控中枢」从 ServeUCentral 键盘钩子迁到 **Nexus 8791 LAN 面板**：host 新增动作注册表 + 状态广播，遥控表面 = Nexus 深色 UI 的「遥控」页（手机浏览器直接打开，零安装零配对），旧 HID 遥控/实体 G20S PRO 经兼容桥继续可用。5 个具体创意（含依赖与难度）见 ideas.遥控交互，优先级建议 1→2→4→3→5。

### 备选
- 仅做服务端动作注册表，遥控 UI 留在手机原生 App 换传输层（HID→HTTP）：保留原生手感，但每次迭代依赖安卓端发版，且放弃「浏览器即遥控器」的零门槛面。
- 键盘钩子监听作为主通道：兼容性最好但受前台焦点/权限限制，仅作兼容模式（创意 3），不做主案。

### 工作量档位：主链（创意 1+2）= **M**；兼容桥 = **M**；第二屏 = **M**（依赖板块一）；体感 = **H**（探索）。

- **库卡一键「AI 生成脚本」+ 进度徽标**：媒体库卡片菜单「AI 生成脚本」→ POST /api/actions/start（任务对象：video_id/status/progress）→ 完成后自动落盘 .funscript 到视频同目录并点亮「脚本就绪」徽标（联动媒体库板块创意 1）（为什么：把「没脚本→找脚本→下载→放对目录」的四步人工流程收敛成一次点击；生成、存储、播放三条链在桌面端首次闭环；依赖：难度：中（控制面+任务编排）｜依赖：板块三控制面与 FrameSource 落地；引擎本体难度另计为高）

## 挑刺意见（必读，影响拍板）

- ⚠ 【必查③】板块一 C「临时挂入 DLNA roots」与代码事实相反，无机制支撑：/api/dlna/roots（host_server.py:2220-2248）是把 roots **持久化**写进设置（:2225 `save_settings({"dlna_roots": roots})`），不存在「临时」概念；且 :2239-2245 注释明说「媒体库是 DLNA 启动期一次性构建的，运行中改 roots 不会热重载」，DLNA 运行中返回 need_restart=true。所以「库卡一键投头显」要么重启 DLNA（打断头显正在进行的 DeoVR 浏览/播放会话），要么新目录根本不在头显里出现。草案把它写成现成能力的拼装，实际两头都不成立。
- ⚠ 【必查①】「pywebview 无原生渲染面嵌入点」这个判断本身成立——实测 venv 装的是 pywebview 6.2.1（pip show），`inspect.signature(webview.create_window)` 全部 34 个参数里没有任何原生句柄/子窗口/渲染面入口，platforms 只有 edgechromium.py/winforms.py；NexusApi（host_server.py:3241-3327）只暴露 win_minimize/win_hide/win_close/pick_folder/pick_file；全仓 grep libmpv|SetParent|pygame|python-vlc 仅命中 dist-app 里 protobuf 的无关误报，ui/ 是纯 HTML+JS，确无混合先例。但草案由此推出的门槛「仅当 HEVC/老编码覆盖成为硬需求时再立项 libmpv」站不住：remux 成 fMP4 只换容器不换编码（草案自己也承认），而本产品生态（DeoVR+DLNA+funscript）的主流素材恰是 HEVC 4K+ VR 视频；Windows N 版连 H.264 都要另装 Media Feature Pack。把最大宗内容格式定为「一期不承诺」且没有任何启动时解码能力探测/报错 UI，播放器一期交付即可能对大半库不可用。（HEVC 依赖系统扩展这点正确，但我未在本机实测目标机器解码能力，属未验证的领域常识。）
- ⚠ 【分期自相矛盾】一期交付「预设独立页 + 播放页 QuickMoves 条」和「遥控创意 1」，但 bleak 设备通道被排到二期（草案分期建议节）；实测 `.venv/Scripts/python.exe` grep bleak|bluetooth 只在 vendor/audiocpp 模型词表（tokenizer.json/vocab.json 词条）命中，桌面没有任何实时设备输出通道。于是一期的 24 卡预设、急停/爆发/缓动、遥控页的玩具动作全部是驱动空气的 UI。草案板块二自己的否决判据（「放播放页没有信息价值」）同样适用于「没有设备的预设页没有用户价值」。
- ⚠ 【必查④】板块三「契约先行」押错了契约形状，正是 YAGNI：一期明确只做离线（FrameSource=LocalFile，实时 ChunkFrameSource 二期预留、单独立项），离线批任务的天然契约是「任务对象+进度+最终落盘 funscript」，POST start + GET status 轮询即可（现有 /api/sync/*、字幕 /api/subtitle/status 同款，host_server.py:2270-2278/2256）。草案却把 SSE 增量 delta 事件流定为输出契约（板块三第 3 条）——SSE 只在实时链有收益，等于为未立项的二期功能提前固化流式协议，并为它预留 FrameSource 双实现。mock 正弦引擎要验证的「SSE→播放器注入→热力图」也是实时链的链，不是离线链的链（离线链=启动→进度→落盘→徽标/同步分发）。
- ⚠ 【必查⑤延伸】板块四创意 3「与 ServeUCentral 并行运行也不冲突（Nexus 只读键不抢占）」站不住：低级键盘钩子是非消费的观察者，ServeUCentral 与 Nexus 会**同时**收到同一 F13–F19 按键，一键双动作（两个 app 各自驱动各自的设备通道）。证据：HidRemoteController.kt:34-36（电脑端全局键盘钩子拦截后执行动作，与 G20S PRO 同一通道）、README.md:181。且 README.md:182 与 HidRemoteController.kt:41-42 明确「按住由电脑键盘重复率自动连发」——Nexus 钩子还会收到连发洪流，动作注册表需要去抖/让位机制，草案只字未提。
- ⚠ 【必查②/缺依据】缩略图管线未区分本地盘与网盘挂载根：草案引 vr_dlna.py:9-11 的设计动机正是「对每个视频同步 ffprobe，网盘上必然超时」才改成零探测，但板块一 B 的「多文件夹扫描+索引+逐视频 PyAV 抽帧」没有对挂载根做任何降级，会把同一超时模式搬进库页（每视频一次随机读，网盘上更慢）。另外「~10% 进度抽 1 帧」对片头黑屏/纯色开场会产出废图，无重试/多候选策略。
- ⚠ 【小失实】草案「已运行检查」声称 `grep -rin bleak|bluetooth host_server.py vendor ui → 零命中`——我按原文重跑，实际命中 vendor/audiocpp/assets/model_manager/vibevoice_1_5b/tokenizer.json、vocab.json 多处（BLE 词表，非代码）。结论「桌面无 BLE 能力」成立，但「零命中」作为已运行检查的表述不实，说明该检查没按声称的命令执行过或没看输出。
- ❓ 【必查⑤核心事实】遥控 5 个创意**均不需要手机发版**（1/2/4/5 全在手机浏览器侧，3 在 Windows 侧），这是浏览器化路线的真正卖点，草案反而没点透；唯一需要发版的是草案自己已降级的备选「原生 App 换传输层」。但发版成本比草案感知的更重：手机仓头 versionName=0.18.2/versionCode=101（app/build.gradle.kts:31-32，版本更新说明.md 记录 2026-09-29 发布），且发布纪律是「仓库与公开 Releases 均只保留最新一个 APK」（版本更新说明.md 版本管理规则节）——用户装的 v0.15.x 落后仓头数版，改手机端=发版+用户侧载+旧版兼容三重成本。
- ❓ 【LAN 面兼容纪律】8791 既有四条路由是存量 APK 的生存面：host_server.py:2609-2611 注释明说「已发布的头显 APK 仍会调这两个（已删缓存）接口」才保留空壳。Nexus 的 /api/remote/* 是新增路由不受影响，但草案通篇没有「LAN 面只增不改、语义冻结」这条纪律，后续改 /api/headset/status 或 /api/subtitle/start 语义就会砸存量 APK。
- ❓ 【鉴权缺位】8791 的设计注释（host_server.py:2600-2616）明确「头显是可信设备，但局域网不一定只有头显」，且为安全已去掉 ACAO *（:2619-2622）。草案往 8791 加 POST /api/remote/action（可急停、可驱动玩具、可切模式、可改设置类动作）却没有任何配对码/token 方案；8791 现有 do_GET/do_POST 也**没有** 8790 那道 Origin/Host 栅栏（host_server.py:2183-2191 只在 8790）。「浏览器即遥控器」同样意味着「局域网内任何拿到 URL 的设备即遥控器」。
- ❓ 【遥控页宿主形态未定】UI SPA 挂在 8790（仅环回，host_server.py:105、3493-3495），8791 是独立白名单 Handler（:2599-2616）。把整个 SPA 挂上 8791 等于把设置/adb/quit 全暴露到局域网——正是 :2613-2616 注释反对的事。草案「现有深色 UI 出一个遥控页」必须明确=独立最小静态页挂 8791（复用 styles.css tokens 没问题），而非复用 SPA 路由。
- ❓ 【状态桥降频教训没继承】手机端是分级轮询：播放/缓冲 20ms、暂停/空闲降到 200ms（VideoPlayerController.kt:207-210 注释明说避免 50Hz 无意义唤醒）。草案只写「20ms 节流或 requestVideoFrameCallback」常驻上报 pywebview js_api——每次调用有 promise+WinForms marshal 开销，50Hz 常驻未评估；至少应复刻分级降频。
- ❓ 【单进程承载预案缺失】host 自述「单进程+一托盘、阻塞操作全在后台线程、纯 stdlib http.server」（host_server.py:8-16）。一期要加进同一进程的：Range 视频流（长连接大吞吐）、PyAV 解码+JPEG（CPU 密集，实测 4K 单帧也有几十 ms）、DLNA、字幕子进程管理。哪些进线程池、哪些独立进程，草案没有划分；缩略图批处理与 /api/state 轮询抢 GIL 的退化模式无预案（字幕服务用子进程+reclaim 正是为了隔离，板块一没有对等安排）。
- ❓ 【quickmoves 与 preset 的互斥语义没对齐】手机事实是 startPresetPlayback 会同时 stopOrgasm/stopSlow（AppViewModel.kt:3534-3537），即手机是三态互斥而非「quickmoves 只与脚本同步互斥」。草案模式管理器把 {script_sync|preset|quickmoves} 列为三态却未说明 preset↔quickmoves 的桌面语义是继承手机（互斥）还是改为共存，两引擎共用加工链时这是行为分叉点。
- ❓ 【两套索引一致性】同一目录既是库根又是 DLNA root 时，媒体库 mtime 增量索引与 DLNA「启动期一次性构建」的媒体库（host_server.py:2239 注释）是两份独立快照；草案未说谁权威、扫描器是否合一。
- ❓ 【/media/stream 暴露面声明】/media/stream?path= 挂 8790 环回没问题，但其「路径必须落在已配置媒体根内」用的正是 DLNA roots 同一份配置；应显式声明该端点永不加入 8791 白名单，否则遥控/未来 LAN 需求一复用它，环回前提即失效。

## 架构级建议

- 把「设备输出通道的最小切片」提进一期：bleak connect + moveTo（复刻 BleDeviceService.kt:711-725 加工链）+ 急停三件事即可让一期预设/QuickMoves/遥控可被验收；否则一期应改口径为「UI+引擎桩，二期接设备」，避免交付驱动空气的页面。
- LAN 面立两条纪律并写进方案：①只增不改——8791 四条既有路由语义冻结（存量 APK 兼容，先例 host_server.py:2609-2611）；②显式配对——新增遥控路由必须带「桌面 UI 显示 PIN→遥控页换长 token」的准入，任何玩具/急停动作不走无凭证端点；同时显式声明 /media/stream 与 8790 SPA 永不进 8791。
- 播放内核先做解码能力探测再做兜底：启动时用 H.264/HEVC/VP9 短样本 canplay 探针生成能力矩阵并经 /api/state 暴露，起播失败按矩阵路由——容器问题走 PyAV remux，编码缺失直接报「系统缺 HEVC 扩展」并给出 os.startfile/mpv-IPC 外部播放兜底（草案已有该备选）。把「是否立项 libmpv」变成由用户库实际编码分布驱动的数据决策，而非拍脑袋的「一期不承诺」。
- 板块三契约瘦身：一期只冻结「POST /api/actions/start（任务对象）→ GET status（进度）→ 产物 funscript 落盘并登记进媒体库与 /api/sync 扫描范围」三级轮询契约，SSE/delta 与 FrameSource 双实现推迟到真引擎选型之后；mock 引擎同样走轮询契约即可验收控制面，省掉为未立项实时链固化流式协议的浪费。
- 媒体库扫描器按根类型分级并做成单一模块：本地根=全量索引+后台 PyAV 缩略图（实测量级安全：1080p 中位 13ms、4K 47ms/张，500 个≈15s，本机 NVMe+mpeg4 合成片的乐观下界）；网盘挂载根=只列文件名+funscript 徽标、缩略图点开时惰性抽取（与 vr_dlna.py:9-11 零探测同一逻辑）；该扫描器同时喂库页与 DLNA 媒体库，消灭两份索引并顺带解决一致性。
