# AI 字幕模型组合评测报告（SIVR-002 · 600s 片段 · 全 GPU）

## 一、现有评分机制审计（要不要改？要。）

**总评**：要改。框架底子是诚实的——区间并集发声时长、短句「不可判定」单列、信任过滤三阈值、上界标注、code_sig 防陈旧实例、失败块计数，这些都是真修（我在代码里逐一核实了），2026-09 那批口径修正有效。但有两类会误导选型的结构性漏洞：覆盖率对文本全盲（乱码/幻觉也算识别到），以及出字延迟根本没量用户要的那个数。最要紧三件事：① 重做出字延迟口径——锚点从段 start 修成 end（measure_emission_lag.py:92 与自家 docstring:4 矛盾，实测同场景 3000ms vs 0ms）、以「中文译文非空的首次响应」为出字时刻、把服务端现成的 total_ms 纳入，否则用户关心的「最终出翻译字幕延迟」从未被测量；② 覆盖率补文本维度并加幻觉/复读罚则——纯时间重叠的召回对识别错误和幻觉全盲，90+ 轮迭代可能在优化一个盲指标；③ 时序补 end 误差与 p90、修 max 统计 bug、全部配对与可信配对同报（去幸存者偏差）。次要但值得顺手做：partial 产物进评分视野、run_eval 出机器可读分数加回归门槛、clean() 加 NFKC 宽度折叠。本次为只读审计：运行过的检查=评分函数级 demo（归一化/最大值 bug/recall 边界/延迟锚点）、62 份 eval 产物与 2 份 lag 产物扫描、grep 验证 compare 脚本不读 meta；未运行完整评测管线（需起服务+模型+音频，属评分实现而非审计范围）。

- **出字延迟·锚点（sivr002 全片实测 p50=2540ms/3200ms）**（high）：measure_emission_lag.py:92 实际算的是「块音频末端 − 段 start_ms」（c - (s or 0)，seen 的键是 (start_ms,end_ms,text)），与 docstring:4 声称的「−段 end_ms」直接矛盾——实测同一场景代码得 3000ms、按文档得 0ms，每个延迟被虚增了整句时长，lag_r634chunk.json 里的 p50/p90 没法按「说完→出字」解读。 → 改进：锚点改为段 end_ms，输出 p50/p90（秒）；修代码与 docstring 的口径分裂。
- **出字延迟·是否量到最终中文译文可用时刻（重点疑点）**（high）：没量到，三处独立缺口：①seen 以日文 text 为键、从不读 translation 字段（measure_emission_lag.py:86-88），空译文的段照样算「已出字」；②docstring:6 自认不含 ASR/MT 处理耗时，而服务端响应里现成的 asr_ms/mt_ms/total_ms（vendor/subtitle/server_app.py:950-951）被脚本丢弃，offline_to_json.py:114-117 打印的 req_time 也没被并进任何延迟指标；③用的协议块末端而非响应到达墙钟。翻译虽是请求内同步完成（server_app.py:899-906），但当前数字只是块粒度协议下限，不是用户关心的「最终出翻译字幕延迟」。 → 改进：以「该段 translation 非空的首次响应」为出字时刻，delay = 响应完成墙钟 − 段 end_ms；用响应自带 total_ms 与协议 lag 交叉分解验证；空译文段进「未出译」不进延迟分子分母。
- **语音覆盖率/识别召回**（high）：配对与命中判定纯看时间重叠≥毫秒阈值（compare_with_reference.py:205-206、:264-267），完全不检查任何文本——输出乱码、复读幻觉、占位字幕都算「识别到」；反向地，漏识把「服务端报错没出段」也一并算成 ASR 漏识（load_mine 不读 meta，见 partial 条目）。 → 改进：命中加文本佐证条件（与人工译文 char-LCS≥0.3 或共享≥1 个 2-gram），纯时间重叠单列为「有时段无内容」不进识别召回。
- **幻觉/多识罚则**（high）：「我有、人工没有」整类豁免为「多为语气词/切分，非错误」（compare_with_reference.py:274），全脚本无复读检测、无幻觉率；而服务端明明有「整句复读置空」缓解（server_app.py:925-927），其效果在评分里只体现为「译文为空」硬缺陷——缓解成功被记成新增缺陷。 → 改进：新增幻觉率指标（同一句全片出现≥5 次或段内连续重复≥3 次判幻觉段）；空译文段标注来源（error=untranslated_leak 等）区分「漏译」与「幻觉被拦下」。
- **译文内容覆盖率（LCS recall）与 clean() 归一化**（medium）：recall 只奖漏不罚错（实测：ref「早上好」vs 带幻觉尾巴的译文 recall=1.0；无关文本也有 0.33 底噪），空/纯标点参考句恒返 1.0（:145-147），单字参考句二值化；clean()（:129-131）无全半角折叠——实测 'ＯＫ１２３ｱｲｳ' 原样保留、半角片假名逃过假名漏译正则（KANA 实测 False）；拼接段落在人工句时间范围外的字也进 LCS，脚本自认是上界（:39-41）并量了 out_ms（:225-226）却从不在分数里扣减。 → 改进：clean() 加 NFKC+宽度折叠（全角拉丁/数字、半角假名→全角）；clean(ref)<4 字的配对单列不可判定；同报「范围内召回」（按区间交集裁剪后）与上界召回两个数。
- **时序指标（起点偏差）**（medium）：只量起点 dt=best 段 start−ref start（:232），无 end 误差、无 p90（只有中位、≤500ms/≤1000ms 占比）；「最大」用 abs(dts[-1])（:286）——实测全负分布时把 900ms 报成 100ms；且只在 trusted 配对上统计（:289），对齐最差的配对恰好被信任过滤（:237-241）先行剔除，属幸存者偏差，回答不了「字幕对不对得上画面」。 → 改进：每对算 start/end 双误差（my 端取落在人工句时间范围内的最早起点/最晚终点），报中位+p90；max 改 max(abs(d))；「全部配对」与「可信配对」两套都报。
- **长度比**（medium）：只在 trusted 配对上取中位（:309-310），空译文段以 0 进中位数拉低读数、越界拼接文本推高读数；「<1 偏简略，>2 偏啰嗦」无 ja→zh 校准依据，无分布（p25/p75/p90），逐句只有中位数一个结论。 → 改进：空译文段剔除（进缺译指标）；输出分位数分布；用本片人工字幕自身的 ja→zh 字数关系校准正常带（如 [0.6,1.6] 正常、>2.5 或 <0.4 异常）。
- **部分失败/空结果产物**（low）：offline_to_json.py:119-132 只在全部块失败时才非零退出，partial 产物带 failed_chunks 标记但 compare_with_reference.py 通篇不读 meta（grep 'meta|partial|failed' 零命中），run_eval.py:226-241 照常评分——一次瞬时 500 会静默伪装成漏识升高；实测现存 62 份 eval_*.json 里 0 份 partial，属潜伏洞未被触发过。 → 改进：评分器读 meta.partial 并在报告头部显式标注；失败块覆盖的时段从漏识分子/分母剔除。
- **评测流程与回归门槛**（medium）：run_eval.py:99-106 默认单视频单 180s 切片，指标全靠控制台肉眼看、无机器可读分数，return 0 与指标值无关（:241）；延迟和质量测的还是不同视频（measure_emission_lag.py:28 用 sivr002，run_eval 默认 sivr001）——90+ 轮迭代没有可自动比对的门槛，容易在单切片上过拟合。 → 改进：评分输出机器可读 JSON；对漏识率、覆盖率中位、start/end 误差 p90、空译文率、延迟 p90 设可配置阈值，超限非零退出；≥2 视频×多时段，延迟与质量用同一内容。
- **译文夹英文判据**（low）：LATIN=[A-Za-z]{2,} 且要求 jp 无拉丁（compare_with_reference.py:56、:253-254），中文译文里合法的 OK/AI/专有名词在 jp 是片假名时会被计为硬缺陷，无白名单。 → 改进：加常用合法词白名单，或要求与 jp 侧片假名转写对应才算泄漏。
- **配对覆盖率 cov**（low）：cov=各命中段重叠之和/人工句长（:221-222），碎片多时重叠和可超句长，cov>1 无 clamp，使 span_ratio 之外最关键的 trust_min_cov=0.5 门槛更易被碎片段通过。 → 改进：cov 改用区间并集重叠并 clamp 到 1.0。
- **辅助统计的整合度（quality_stats.py）**（low）：quality_stats.py:36-39 的「译文与原文完全相同」「译文含假名」是现成的未翻译/复读代理指标，且假名正则已与主脚本对齐（:33-35 注释），但游离在 run_eval 主循环外，不进评分结论。 → 改进：把 identical/假名/空译文三个计数并入主评分输出，作为「未翻译率」单一指标。

复核后交付的改进评分器：tests/score_combo.py（coverage、precision、timingP50ms、timingP90ms、lenRatio、lagP50s、lagP90s、missingCount、sentenceCount），冒烟自测通过。
