## R112 追加修：速度滑轨关联态搞反

`sliderRowHtml(label, valueText, id, min, max, val, enabled)` 的第 7 个参数是 **enabled**，
一键爆发那处把「关联上限的勾选状态」直接传了进去 → 勾上=可拖（蓝）、不勾=禁用（灰），**正好反过来**。
其余 4 条滑轨传参复核无误。改为传 `!bSpeedLink`，与手机一致：**勾了关联 → 禁用（跟随主上限）；没勾 → 可拖蓝色**。

真机实测（热重载）：

| 状态 | 速度轨 | 数值 |
|---|---|---|
| 未勾关联上限 | 禁用=false、透明度 1、填充 rgb(74,95,138)、pointer-events auto | 500 Units/s |
| 勾上关联上限 | 禁用=true、透明度 .45、pointer-events none | 500 Units/s（关联主上限） |
| 取消勾选 | 恢复蓝色可拖 | 500 Units/s |

待机缓动·范围同口径核对：未勾=可拖 0%-100%；勾上=禁用 +「关联主输出」。

## R112 追加修：热力底改回"整条同色"

上一版按"类渐变色"做成了 135° 横向渐变（类白 → 淡紫），用户看后要求**整条统一用右侧那个淡紫**，不要渐变。
现为平铺同色：亮色 `#ece9f5`（类白偏淡紫）／暗色 `#1c1728`（类黑偏深紫），零速档的插值起点就是底色本身。
实测画布左端/中间/右端像素完全相同（亮 236,233,245 ／ 暗 28,23,40），`background-image:none`。

# 五、R113：内置播放器 + 功能接线审查

## 1. 内置播放器（用户硬要求：同一窗口、点击即播）

**技术路线**：HTML5 `<video>` 直接播放，流地址优先 /api/library/stream（1.0.56+ 宿主接口），

## R113 追加：窗口按钮顺序 + 最大化失效（真 bug）

**顺序**：用户要求按 Windows 惯例 = **最小化 / 最大化·还原 / 关闭**（原来是 最大化/最小化/关闭）。

**最大化点了没反应 —— 根因在宿主**：
`win_maximize` 用了 `ctypes.wintypes.WINDOWPLACEMENT`，而 **ctypes.wintypes 里根本没有这个结构体**
（只有基础类型），调用必然抛 AttributeError；前端还把返回值吞了，所以表现就是"完全无效"。
实测宿主原样返回：`{"ok": false, "error": "module 'ctypes.wintypes' has no attribute 'WINDOWPLACEMENT'"}`。

两层修：
1. **宿主真修**（host_server.py）：自建 POINT/RECT/WINDOWPLACEMENT；句柄不再靠窗口标题，
   改成 EnumWindows 枚举**本进程**的可见顶层窗（标题会随页面变）。实测：
   `sizeof(WINDOWPLACEMENT)=44` ✓、`GetWindowPlacement` 返回成功 ✓、showCmd 可读 ✓。
   —— 但这段在 exe 里，要 **1.0.56** 才生效。
2. **前端兜底（今天就能用）**：调宿主，返回 ok:false / 抛错 → 退到全屏 API（无边框窗口下≈最大化），
   图标与提示同步成"还原"。实测点击：全屏 true、图标 #i-restore、提示"还原"；再点还原 ✓。

### 实测结论：1.0.55 exe 里"最大化"从**前端**无解

| 路径 | 实测结果 |
|---|---|
| pywebview 桥 `win_maximize` | 返回 `{"ok":false,"error":"module 'ctypes.wintypes' has no attribute 'WINDOWPLACEMENT'"}` —— 宿主代码写错了 |
| 全屏 API 兜底 | `document.fullscreenElement` 会变 true，但**窗口一动不动**：点击前后都是 `960x806 at 360,103, IsZoomed=False`。WebView2 的 requestFullscreen 只改 DOM，pywebview 不处理 ContainsFullScreenElementChanged |
| HTTP 层 | 只有 `/api/win/show`（托盘唤起），没有任何窗口操作路由 |

→ 前端所有路都堵死，**只能改宿主**（源码已修好并单独验证：sizeof(WINDOWPLACEMENT)=44、GetWindowPlacement 成功）。
按用户要求，按钮不再做"假装在动"的全屏兜底，改为**如实提示**"最大化暂不可用 · 装 1.0.56 后恢复"。

# 七、全屏后点返回卡死（R113 热修，ui-only）

## 现场

用户：全屏播放后点「返回媒体库」→ 整个窗口卡死。
实测现场：宿主进程 Responding=True、API/HTTP 正常、页面 JS 线程也活着（`performance.now()` 800ms 正常递增），
但 **WebView2 GPU 进程烧了 562 秒 CPU** —— 是合成器在自旋，不是 JS 死循环。
DOM 快照：`fullscreenElement = vlVWrap`，而它的祖先 `#vlPlayView` 已经是 `display:none`。

## 根因

全屏元素是 `#vlVWrap`；返回时我把它的祖先 `#vlPlayView` 设成 `display:none` →
**一个仍在 fullscreen 状态下、却没有布局盒的元素** → Chromium 合成器反复尝试解析它的几何 → GPU 打满 → 窗口假死。

## 修法

1. 全屏元素改成 **`document.documentElement`**（文档根）：这样隐藏任何子容器都不会让全屏元素失去布局盒；
   画面靠 CSS 自己铺满屏：`html:fullscreen .vl-vwrap{ position:fixed; inset:0; z-index:80; border-radius:0 }`。
2. 返回时**先 `exitFullscreen()` 再动 DOM**（双保险），并接住它的 promise（否则控制台冒 `Permissions check failed`）。
3. 验证时又发现两个连带 bug 一并修掉：
   - 返回只用缓存的 videos 重画 → **子目录卡丢失**（多目录时返回后是空视图、还进不去子目录）→ 改成重新拉当前目录；
   - 每秒轮询看到「mpv 播放器没了」就把视图踢回根目录 → 从 `E:\testvideo` 返回会变成「媒体库」→ 改成只在**人正停在播放视图**时才回根。

## 复验（真机 1.0.56 + 可信鼠标事件，全屏带用户激活）

```
① 进 E:\testvideo        标题=testvideo  夹 1 张  视频 6 张
② 播 K1cztm.mp4          播放中 1920x1080
③ 点全屏                 fullscreenElement = HTML（文档根）
④ 全屏中点「返回媒体库」  全屏已退 ｜ 视图=浏览 ｜ 标题=testvideo ｜ 夹 1 张 ｜ 视频 6 张 ｜ 计数「1 个目录 · 6 个视频」
   GPU 增量 2 秒（卡死那版是几百秒自旋）
⑤ 再播一次               正常
   运行时异常 0
```

> 本次全是 `ui/*` 改动 → **热替换即可生效**，不用重打包。
